PRE-LAUNCH INPUT AND MULTI-CONTROLLER AUDIT — 2026-10-07

INPUT BUGS FOUND
1. Held keyboard auto-repeat could repopulate gameplay inputs after clear(), including screen/pause transitions. Reproduced with KeyJ -> clear -> repeated KeyJ. Fixed by rejecting repeat events for keys no longer held by the input manager; a fresh keydown still works.
2. Focus loss cleared current keys but did not prevent subsequent controller polling from restoring input while unfocused. Fixed with a focus gate on polling/consumption and cleanup on focus return. Held controller buttons must return to neutral before resuming. No automatic match pause was added; online simulation remains unchanged.
3. Queued Escape/debug/training-reset commands survived clear()/blur. Fixed by clearing systemActions along with gameplay inputs.
4. Holding R generated repeated training resets through keyboard repeat. Reset is now edge-triggered, consistent with existing pause/debug commands.
5. Controller menu events survived input suppression. A queued confirm/direction could execute after clear, disconnect or reassignment even though its gameplay mask had been cleared. Device suppression now removes that device's pending menu events, retaining connection/assignment notifications.
Five failing regression cases established the keyboard, system-queue and controller-queue failures before edits. An additional focus/controller polling regression covers the focus gate.

CONTROLLER ASSIGNMENT BUGS
Confirmed: queued menu events retained their old player after reassignment (issue 5). Fixed at the shared suppression boundary used by assignment, release and disconnect.
No duplicate simultaneous ownership reproduced. assign() removes a device's old seat and releases an occupied destination. Disconnect retains a reserved seat; menus allow an unassigned device to reclaim missing seats. During gameplay, main.ts explicitly routes recent activity on an unassigned standard device to a missing active seat. A connected device already assigned elsewhere is not silently stolen.
Browser index gaps/order changes and identical model strings are covered by tests. Device records use session keys, not model names as unique physical identities. The code cannot identify which identical physical controller was replugged; explicit rejoin/reassignment is intentional.
Keyboard layouts remain fallback inputs for P1/P2 even when a controller occupies those seats. This is existing intentional behavior, not exclusive keyboard ownership. Claim keyboard seats before controller join when mixing input methods.

PLATFORM/BROWSER LIMITATIONS
Only devices reported with mapping='standard' are assignable. Non-standard devices remain visible for diagnostics; the code does not guess vendor-specific button layouts. Brand recognition affects labels only.
The game consumes what navigator.getGamepads exposes; successful simulated tests do not prove a particular browser/OS/USB/Bluetooth setup exposes eight devices. Actual mappings, simultaneous button behavior, keyboard rollover, wireless reliability, and real focus events require hardware testing.
Disconnected device records are retained in-session for identity/history; repeated reconnections grow that diagnostics collection. No practical failure reproduced, but an unusually long hot-plug soak should monitor it.

REALISTIC MAXIMUM CONTROLLER SETUP
Configured software ceiling: eight independently assigned controller seats (MAX_LOCAL_GAMEPADS=8). The automated eight-pad configuration passes. Six-to-eight physical controllers remain a release qualification target, not a certified hardware result.
For mixed keyboard/controller play, reserve P1/P2 for keyboard and use six pads in P3–P8. The supported eight-pad seat range does not extend to seats 9–16 even though some match modes allow sixteen fighters. Do not advertise sixteen local controller players on this implementation.
