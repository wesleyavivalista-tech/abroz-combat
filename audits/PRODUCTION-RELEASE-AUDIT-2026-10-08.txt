CONFIGURATION ISSUES
- Web fallback relay is page host :8080; typical public HTTPS hosting needs explicit
  VITE_WS_URL rather than relying on this fallback.
- Client art/audio URLs are root-relative. Domain-root hosting supported; deploying
  under a nested /game/ prefix is not verified or fixed by Vite base alone.
- Code chunks are hashed; public art/audio paths are generally not. Do not apply
  immutable caching to all files. Revalidate HTML/unhashed assets, deploy atomically,
  and retain old hashed chunks briefly to avoid stale-session import failures.
- pnpm-lock.yaml is the lockfile; use pnpm install --frozen-lockfile for reproducible
  dependency installation. No clean dependency reinstall was performed in this audit.
- Environment variants such as .env.production were not covered by the original
  .gitignore. Added .env.* with an exception for .env.example.
- Desktop signing/icon/publisher warnings are understood but require release inputs.
- Total web artifact remains 1,351,076,252 bytes (~1.26 GiB). It is not all loaded at
  startup, but affects hosting uploads and desktop download/storage size. Remaining
  legacy variants require a full dynamic asset-use inventory before further pruning.
  Largest source file is the superseded 21.5 MiB main-menu-user.wav; left untouched
  in this targeted audit rather than deleting user-supplied source material.

DEPLOYMENT ASSUMPTIONS

Relay behind a WebSocket-capable TLS proxy with explicit origin and connection limits.
Rooms are in-memory; no automatic multi-worker shared-session persistence exists.
Deploy matching simulation revisions on client/server. Standard local-only desktop
build intentionally offers an explanatory error if online play is attempted.
Asset errors have bootstrap/retry UI and nonfatal audio fallbacks; graphics-driver,
real-host cache, CDN partial-deploy and cold-network failure behavior still need QA.
