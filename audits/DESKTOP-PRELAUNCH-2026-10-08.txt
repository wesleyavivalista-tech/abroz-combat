Date: 2026-10-08
Scope: current working tree; Electron macOS ARM64 package built and exercised here.
Existing uncommitted work was preserved. No gameplay, assets, balance, browser code,

DOWNLOADABLE RELEASE BLOCKERS
1. Public distribution artifacts are not validated. This run produced an unsigned
   macOS ARM64 .app directory, not a signed/notarized installer. Windows NSIS,
   Linux AppImage, Intel Mac, clean installation and upgrades remain unverified.
2. No production relay was supplied for this audit. The artifact is explicitly
   OFFLINE. Online distribution requires the production WSS endpoint and real
   desktop/browser interoperability tests against the deployed server.
3. The working tree contains substantial pre-existing uncommitted/untracked game
   code and assets. A clean clone cannot be certified as this tested release until
   the intended release inputs are captured. No fresh dependency install was run.

CRITICAL ISSUES
No new confirmed desktop-specific crash/data-loss vulnerability in the inspected
paths. This is not proof that all drivers, installers and hardware are safe.

HIGH-PRIORITY ISSUES
Fixed: release packaging accepted wss://localhost and other loopback destinations.
That can ship online play pointed at each player's own machine. The previous check
validated WSS and absence of credentials, but not a development-only host.
Remaining: signing, deployed relay and clean-machine validation above.

MEDIUM ISSUES
Fixed: generated buildVersion was not visible to players or included in startup
logs. Reports could not readily distinguish builds with the same game version.
ABROZ_BUILD_VERSION must still be set to a unique release identifier; default is
package version 0.1.0, so builds using that default remain indistinguishable.
Installer/upgrade interruption and OS-level profile corruption are not tested.
Package is large (about 1.7 GiB unpacked including runtime); no assets removed.
No automatic updater exists; manual replacement/update needs release instructions
and validation that app identity/origin/user-data path stay stable.

LOW ISSUES
Packaging warns about missing author/publisher and uses the default Electron icon.
Offline online-mode feedback is clear, but appears after entering the lobby and
pressing Create Room. Not changed: no menu redesign was requested.
No dedicated borderless-window mode or Alt+Enter mapping found; native fullscreen
is supported. Window placement is not persisted, avoiding stale saved offscreen
coordinates but not proving behavior across monitor changes.

FIXES IMPLEMENTED
A. Release endpoint validation
   Files: apps/desktop/policy.mjs, scripts/desktop.mjs,
   tests/desktop-policy.test.mjs.
   Reject missing/insecure/credential-bearing URLs and literal loopback hosts,
   including localhost subdomains. Explicit --offline clears the endpoint.
   Development loopback flow is unchanged. No protocol or gameplay changes.
   Regression covers valid production WSS, offline override and rejected inputs;
   failure messages do not echo the supplied URL/credentials.
   Limitation: this is a configuration guard, not DNS validation; it cannot prove
   that an arbitrary hostname is a reachable production service.
B. Visible build identification
   Files: apps/desktop/policy.mjs, apps/desktop/main.mjs,
   tests/desktop-policy.test.mjs.
   Window title includes game version and optional distinct build identifier.
   Page title changes cannot erase it. Startup log includes the build identifier;
   newlines are removed and length bounded. No renderer/UI gameplay changes.
   Tested title formatting plus real packaged launch showing v0.1.0.

BROWSER/DESKTOP DIFFERENCES FOUND
Shared renderer, simulation, fighters, modes, input manager and audio engine are
built from the same source. No separate desktop combat/physics implementation.
Desktop uses abroz://game assets, native fullscreen, per-user Chromium storage,
strict local-content policy, single-instance lock and packaged crash handling.
Browser storage is a different origin/profile and does not migrate automatically.
Desktop online builds require an explicit endpoint; browser fallback is unchanged.
Desktop production excludes development pages and has no exposed Node runtime in
the renderer. Chromium/Electron controller/graphics behavior can differ from other
browsers despite shared game code. Full gameplay parity is not empirically proven.
