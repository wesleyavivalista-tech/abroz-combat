2026-10-08 | Baseline e0e730f | macOS 26.6.2 (25G83), arm64
Working tree was clean before this audit. No source/gameplay changes made.

MACOS RELEASE BLOCKERS
1. The produced app and nested bundles fail code-signature verification. The
   linker ad-hoc signature is not a valid Developer ID distribution signature.
2. No stapled notarization ticket. Gatekeeper assessment does not pass. Local
   non-quarantined launch is not proof that a downloaded copy is installable.
3. Only Apple Silicon has an artifact/runtime test. Do not advertise Intel or
   Universal support on the evidence from this audit.
4. The tested artifact is deliberately offline. If online play is advertised,
   supply production WSS and verify real Mac/browser/Windows complete matches.
5. Clean-user/OS, physical controller/audio/display and sleep/wake tests remain.
   Existing-profile testing does not establish a clean-machine certification.

CRITICAL MACOS ISSUES
No new confirmed macOS gameplay crash or data-loss issue found in tested flows.
That conclusion is limited to the build, code review and smoke coverage below.
Signing failure remains a distribution blocker even though the local app runs.

HIGH-PRIORITY ISSUES
Invalid distribution signatures on the main app, all four helper apps and all
four framework bundles checked. codesign --verify --strict fails for each with
'code has no resources but signature indicates they must be present'. Deep
verification also fails. Do not distribute this artifact as a signed release.
The app has no notarization ticket; downloaded/quarantined launch remains open.
Real production cross-platform gameplay and network-denial recovery are untested.

MEDIUM ISSUES
- Version/build defaults both remain 0.1.0. Set a unique ABROZ_BUILD_VERSION and
  release version when making distributable releases.
- Runtime inherits Electron Info.plist usage descriptions for camera, microphone,
  audio capture and Bluetooth, plus permissive ATS/local-network defaults.
  A declaration alone does not request access. No capture/WebBluetooth request
  was found in game code, and permission handlers allow only fullscreen.
  No corresponding prompt appeared during the tested flows. Revisit inherited
  metadata before public release; do not remove Bluetooth support speculatively.
- hardenedRuntime:true is configured, but cannot be certified on an unsigned
  artifact. Builder defaults include JIT, unsigned executable memory and disabled
  library validation entitlements. Validate the final signed app and helpers;
  do not remove runtime entitlements without signed-build compatibility testing.
- DMG is 1,469,181,769 bytes (~1.37 GiB); install needs additional disk space.
- No automatic updater exists. Keep app identifier and profile/origin stable
  during manual updates; version-changing and interrupted updates untested.

LOW ISSUES
Default Electron icon and empty publisher/author. Bundle display name is Abroz
Combat, while the actual filename is abroz-combat.app. This is cosmetic, not a
launch failure. No dedicated borderless mode or Alt+Enter binding implemented.

NOTARIZATION STATUS
NOT PERFORMED. xcrun stapler validate reports no ticket on the app.
Installed electron-builder supports notarizeIfProvided, and its notarization
library staples after a successful submission. No custom disabled-notarization
setting was found. This configured capability is not a successful submission.
Remaining release steps:
1. Release owner supplies an existing Developer ID Application identity securely
   and chooses a supported notarization credential/profile through the release
   environment (never committed to the repository).
2. Rebuild with signing enabled; do not use CSC_IDENTITY_AUTO_DISCOVERY=false.
   Set release metadata/build ID and enable forceCodeSigning for the release job
   so signing failure cannot silently produce a release candidate.
3. Allow builder notarization with its supported keychain-profile or Apple API
   credential flow; require success. No credential values belong in logs/report.
4. Verify codesign --verify --deep --strict, stapler validate on final app, and
   Gatekeeper assessment. Inspect final entitlements and signed nested bundles.
5. Verify DMG integrity, notarize/staple the final distribution image as applicable
   to the chosen release workflow, and test the actual downloaded DMG on a clean
   Mac without removing quarantine or bypassing Gatekeeper.
