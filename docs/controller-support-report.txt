ABROZ COMBAT — CONTROLLER SUPPORT REPORT
3 October 2026

1. ARCHITECTURE BEFORE
Gameplay already consumed the shared Button bitmask through InputBuffer. The keyboard had two independent key layouts and pending presses so short taps survived until the next simulation tick. Controller polling lived in InputManager, but browser indices implicitly determined player ownership. Its mapping changed for matches with more than two fighters. There was no controller menu navigation, joining, assignment management, or disconnect recovery.

2. ARCHITECTURE IMPLEMENTED
Physical keyboard / Gamepad API → InputManager + GamepadManager → explicitly assigned local player → existing Button mask → unchanged simulation/InputBuffer.
GamepadManager owns session device records, separate player slots, mappings, deadzone, edges, pending presses, joining, capture for assignment/identification, and diagnostic state. MenuNavigation adapts logical menu actions to the existing DOM controls. main.ts handles screen policy and local/online disconnect behavior.
No fighter, combat, damage, movement, animation, networking protocol, rollback, or authoritative state code was changed for this task.

4. DETECTION
Connection events discover device metadata without consuming the first press. Disconnection events release input immediately. Fresh navigator.getGamepads() samples are read each animation frame and before fixed simulation steps. Polling also discovers preconnected devices and missing disconnect events. Null entries and high indices are supported; no array position is a player number. If the API is unavailable or blocked, controller state clears and keyboard input remains available.

5. ASSIGNMENT
A session key identifies each observed device connection. Player slots store these keys. Browser index, raw ID, presentation name, brand hint, mapping, connection status, assigned slot, current/previous axes and buttons, activity time, logical masks, and pending presses are tracked separately.
One gamepad can occupy exactly one slot. Reassignment frees its previous slot and the prior device in its destination, without moving unrelated players. Disconnected slots remain reserved. No assignments or browser indices are persisted across refreshes.

7. KEYBOARD COEXISTENCE
Both original keyboard layouts remain active for P1 and P2, including when those slots also have a gamepad. Every original action and saved binding is retained. Short taps remain pending until consumed; held/released masks feed the same gameplay buffer as before. Pause, debug, and training reset are now logical system actions from InputManager. Raw key capture remains only where necessary to rebind keys.
Using a layout reserves its seat from ordinary automatic joining; the Controllers page also has explicit Keyboard 1 / Keyboard 2 buttons. With no reserved keyboards, the first pad joins P1. With Keyboard 1 reserved, it joins P2. With both reserved, pads start at P3. Manual Change device can replace a keyboard reservation. Keyboard fallback remains usable for the first two seats.

8. CAPACITY
MAX_LOCAL_GAMEPADS defaults to 8; GamepadManager accepts a configurable cap. All browser-exposed devices are discovered, including devices beyond the active-slot limit. Up to eight pads can occupy eight slots. Keyboard seats use the same local slot capacity. Current match modes retain their original fighter counts; championship entrants are not incorrectly treated as simultaneous input slots.

9. PRESS ANY BUTTON TO JOIN
Menus show a compact join message. A fresh button on an unassigned standard-mapped controller claims an eligible slot, prioritizing a disconnected reserved slot, then the next free seat. Setup screens restrict new joins to their player count. Joining produces a player/device confirmation. The joining press is consumed and the pad must return to neutral before menu/gameplay input resumes. Movement alone does not join.

10. CONTROLLER MANAGEMENT
Open Settings → Controllers, the Controllers button in local setup, or Controllers from local pause. The panel shows all eight slots, connection labels, keyboard alternatives, Change device, Identify, Test, and Release slot where applicable. The device list includes unassigned and disconnected records, raw IDs, browser indices, and mapping diagnostics. A saved deadzone selector ranges from 10% to 40%, default 20%. Returning closes the panel without discarding assignments or the paused match.

11. IDENTIFICATION
Choose Identify for an assigned slot and press that controller. Activity highlights its player card and shows the recognized player/name. The capture completes only for the requested device. Identical controller names do not determine ownership. Haptics are deliberately not required or enabled.

12. MANUAL REASSIGNMENT
Choose Change device on the destination seat, then press the intended controller. Already-assigned controllers may be moved this way. Inputs are cleared and suppressed until neutral. Disconnected assignments may also be released or replaced. P1/P2 can revert to their keyboard layout.

13. TESTING VIEW
Test displays numeric pressure and branded labels for exposed buttons and all axes, including whether an axis is inside the deadzone. An unassigned device can also be tested from the device list. Input testing suppresses menu/gameplay commands while still recording raw diagnostic values. There is no continuous high-level full-screen rerender: diagnostic/label updates are throttled to about 7Hz; per-frame sampling stays in the input layer.

14. DISCONNECT / RECONNECT AND MENU OWNERSHIP
Disconnect releases held and queued pad actions without shifting seats. During local combat, a relevant disconnect pauses the match and displays the missing player. A fresh press from an unassigned standard pad reclaims a missing slot. It does not also resume or attack. P3+ must have connected inputs to resume; the first two seats retain keyboard fallback. Multiple missing seats are recovered in seat order, or explicitly through Change device.
Identical controller IDs are not treated as reliable physical serial numbers: reconnect is an explicit press-based claim, not silent reassignment based on the model name. In menus, press-to-join likewise prioritizes a missing seat.
Online disconnect does not pause the shared simulation: only local input releases, with a reconnect notice. The controller's online Menu opens Return/Leave controls while the match continues. Keyboard Escape retains its previous leave-online behavior.
General menus use a 500ms ownership lease to arbitrate simultaneous pads. In sequential local 1v1 selection, only the current player's pad can select; training/online selection uses local slot 1. Local multiplayer cards restrict each pad to its own card, with P1 owning global setup/start controls. A controller that pauses initially owns the pause menu; keyboard/mouse remain available.

15. BROWSER / PLATFORM LIMITATIONS
Real device support depends on the browser, OS, driver, connection method, and Gamepad API exposure. Some browsers expose a preconnected pad only after interaction. The application supports eight slots, but cannot force the platform to expose eight physical devices. IDs and indices are not stable hardware identities. Secure-context and embedding permissions can affect Gamepad API access.
Reference: MDN, Using the Gamepad API
https://developer.mozilla.org/en-US/docs/Web/API/Gamepad_API/Using_the_Gamepad_API

16. SPECIAL HANDLING
Only mapping === 'standard' controls gameplay. Nonstandard devices remain visible and testable with an explicit unsupported-mapping message; they cannot accidentally feed incorrect attacks. Use a browser/driver that exposes standard mapping. Brand detection affects labels only. Haptics and a full custom nonstandard mapping editor are left for later. Text entry such as online room codes and tournament names still uses the existing keyboard text fields.

18. REMAINING RISKS / FOLLOW-UP
Real wired/Bluetooth Xbox, DualSense/DualShock and generic hardware were not
available for this session. Perform a hands-on acceptance pass on the target
browsers, particularly eight-device OS limits, trigger mapping and reconnects.
Online behavior was audited and covered by the existing simulation/network
regression suite; a live two-computer controller disconnect match was not run.
Results/rematch routing has DOM-boundary coverage, not a complete hardware
match-to-KO walkthrough. Nonstandard controllers need standard mapping support
or a future explicit calibration editor. Existing unrelated test/lint failures
remain visible above. No claim is made that physical hardware was validated.
