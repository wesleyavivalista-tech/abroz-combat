# Abroz Combat audit — September 18, 2026

## Fixed

- Airborne hitstun applied horizontal knockback twice per tick. It now integrates once.
- Projectiles used their owner's current facing for knockback. Impact now follows projectile travel even when the owner turns away.
- Leaving a loading screen could allow a late asset callback to start an abandoned match. Screen revisions now reject stale completions; loading failures return a recoverable error screen.
- Pending room connections now settle when cancelled or closed before opening. Old sockets cannot deliver messages into a new connection; malformed JSON is ignored. Navigation cancels abandoned connections and delayed inputs.
- Keyboard rebinding now cancels on Escape, navigation or selecting another binding. Conflicting assignments swap keys, reserved keys are rejected, and storage failures no longer break control changes. Invalid saved gamepad button indexes fall back to defaults.
- Combat help uses configured keys; online opponents no longer display the local player's super shortcuts. Training dummy controls retain the selected behavior when the HUD is rebuilt.
- Compact menu positioning and roster overflow handling improved. The archive no longer shows match setup progress. Portrait direction, style text and move names come from fighter presentation/data instead of two-character switches.

## Ready for new fighters

- Optional basic attack mappings allow unique move IDs for all three chain moves, heavy, kick, crouch and air attacks.
- Registration checks move references, slot counts/distinctness, move IDs, basic timing and stats.
- The room server validates against the shared fighter registry rather than a hardcoded two-fighter allowlist.
- Presentation registration supplies portrait, style and facing; missing artwork gets a neutral placeholder.
- Updated `CREATING_CHARACTERS.md` with intake information, custom move mappings, portrait/sprite integration and deterministic mechanic requirements.

New mechanics still need implementation and tests. Sprite atlases require appropriate pose coordinates and animation adapters; arbitrary new artwork cannot reuse Vector/Brut's atlas coordinates automatically.

## Validation

- `npm run check`: type checking, lint and **90/90 tests passed**.
- Regression coverage added for single-integration airborne knockback, projectile direction after owner turns, custom fighter move IDs/presentation, and connection cancellation/stale/malformed messages.
- Existing tests cover three-hit chains, heavy/kick separation, platforms/double jump, lives/respawn protection, super allowances, snapshot replay, multi-client rollback and room/disconnect handling.
- `npm run build`: client and server production builds passed. Vite retains its advisory for the approximately 588 kB minified client bundle (157 kB gzip); this is not a build failure.
- Browser: reviewed desktop and compact home layout (1280×720 and 560×420), fighter archive, selection → arena → training, combat HUD, pause/menu return, and Escape cancelling rebinding. No browser console errors observed in this session.

## Scope limits

This is a local development audit, not a guarantee that no bugs remain. Physical gamepads, all browser/device combinations and separate internet connections were not verified. The current sprite animation library is finite; each new fighter needs visual checks across its own transitions and poses. Earlier validation document entries describe historical art/UI revisions.
